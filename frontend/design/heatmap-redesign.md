# 단물지도 UI 개선 근거

## 참고 자료

- [TradingView: Size by / Color by](https://www.tradingview.com/support/solutions/43000707144-how-to-set-up-a-heatmap-what-is-size-by-and-color-by/) — 면적과 색상의 의미를 분리해 안내하고 개별 종목 값을 확인하는 탐색 방식.
- [Finviz: Map View](https://finviz.com/knowledge-base/market-data-research/maps-groups/map-view) — 시장 전체를 업종별로 묶어 읽는 정보 구조 참고.
- [IBM Carbon: Legends](https://carbondesignsystem.com/data-visualization/legends/) — 의미가 명확한 범례와 직접적인 데이터 라벨.
- [IBM Carbon: Color palettes](https://carbondesignsystem.com/data-visualization/color-palettes/) — 중립적인 화면과 의미 있는 색상 강조.
- [W3C: Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) — 일반 글자 대비 4.5:1 기준 참고.

외부 차트나 위젯을 삽입하지 않고 기존 KIS 시세와 UI 컴포넌트를 유지한다.

## 화면 구성

1. 상승률 1위 요약: 시장·기간, 업종명, 등락률을 구분한다. 모두 하락한 경우 하락폭 최소라는 문구를 표시한다.
2. 필터·데이터 기준: 시장/기간 선택, 1분 제한 새로고침, 수집 시각·시세 기준일·출처·장 상태를 표시한다.
3. 시장 지도: 15개 섹터 × 5개 기업을 유지한다. 상승/하락/보합 수는 전체 시장이 아닌 표시 범위 기준임을 명시한다.
4. 연관 섹터: 출발 업종 → 연관 이유 → 대표 기업 순서. 산업 연결과 시장 흐름 참고를 구별한다.
5. 뉴스: 출처 → 제목 → 발행 시각. 실제 데이터 없는 사진이나 기사 요약을 추가하지 않는다.

## 상호작용과 반응형

- 지도/목록을 전환해 동일한 75개 기업을 비교한다.
- 선택한 범위 안에서 기업명·코드를 검색하고 결과 수와 바로 선택할 수 있는 기업을 표시한다.
- 업종 제목 또는 선택 상자로 확대하고 전체 지도로 복귀한다.
- 종목 상세 영역의 최소 높이를 유지해 선택 시 화면 흔들림을 줄인다.
- 모바일 지도는 최소 폭 640px을 유지하고 지도 안에서만 가로 스크롤한다. 확대 지도는 작은 폭에도 맞춘다.
- 1280px 미만에서는 연관 섹터를 지도 아래에 배치한다. 768~1279px에서 연관 카드 3개를 한 줄로 보여준다.
- 뉴스는 모바일 1열, 작은 태블릿 2열, 넓은 화면 4열로 표시한다.
- 카드/본문에 새 애니메이션을 추가하지 않으며 로딩 아이콘은 reduced-motion을 존중한다.

## 데이터 신뢰성과 시각 표현

- 기존 10분 수집과 수동 갱신 60초 제한, Google RSS 연동을 유지한다.
- stale/부분 수집은 별도 문구로 알리고 수집 시각과 시세 기준일을 구분한다.
- 상승 빨강, 하락 파랑, 보합/미제공 회색을 유지하면서 흰 타일 글자 대비를 높인다.
- 범례는 실제 타일과 같은 색상 함수를 사용한다. 색상 외에 부호 있는 등락률을 함께 보여준다.
- 가중치·표시 범위 설명은 펼쳐 볼 수 있는 '데이터와 표시 기준'에 모은다.

## 검증

- 타입 검사, 수정 영역 ESLint, Next.js 프로덕션 빌드 통과.
- 실행 중인 로컬 개발 서버의 /heatmap 경로 HTTP 200 응답 확인.
- 실제 저장 시세의 KOSPI/KOSDAQ × 일간/주간/월간에서 섹터 15개·기업 75개 유지 확인.
- 지도 폭 640/720/900px에서 모든 섹터와 종목 영역이 범위 내에 배치되고 종목 이름 표시 조건 충족 확인.
- 기본 및 호버 상태의 흰색 타일 글자 대비를 계산했으며 최솟값은 약 4.65:1. 검색으로 흐리게 처리한 비일치 종목은 제외한다.
- 브라우저 자동화는 Windows 샌드박스 ACL 오류로 실행되지 않아 실제 스크린샷 및 클릭 검증은 미완료. 수치 검증은 브라우저 시각 검증을 대체하지 않는다.
